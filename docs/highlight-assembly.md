# BLAZZID AI Studio — Stage 4: Highlight Ranking, Duration-Budgeted Selection & Montage Assembly

## 1. Overview & Architecture

Stage 4 delivers the first end-to-end highlight assembly and video rendering engine for BLAZZID AI Studio. Operating on timestamped `GameplayEventCandidate` moments generated by Stage 3 (`blazzid-detection`), Stage 4:
1. Ranks candidates via explainable, multi-factor utility scoring.
2. Solves duration-budgeted highlight selection using 2-dimensional Dynamic Programming Weighted Interval Scheduling (`blazzid-algorithms`), maximizing cumulative highlight value without clip overlap.
3. Plans context-aware source clip intervals with narrative lead-in and lead-out padding, clamped to $[0.0, \text{source\_duration\_seconds}]$.
4. Renders a finished, high-quality MP4 montage with audio/video synchronization using FFmpeg, supporting landscape (16:9) and portrait (9:16) aspect ratios with deterministic canvas fitting.
5. Verifies container readability, stream presence, dimensions, duration tolerance, and playability via headless decode smoke tests.
6. Emits a machine-readable JSON edit manifest recording complete selection, planning, and rendering provenance.

Crucially, **Stage 4 does not introduce generative AI, LLMs, or external APIs**. It establishes an auditable, deterministic baseline with zero black-box magic.

The implementation resides in `packages/assembly/` (`blazzid-assembly`):

```text
packages/assembly/
├── pyproject.toml
└── src/blazzid_assembly/
    ├── __init__.py          # Public package exports
    ├── models.py            # RankedCandidate, PlannedClip, EditPlan, ValidationReport, EditManifest, AssemblyResult
    ├── config.py            # AssemblyConfig, RankingConfig, and predefined ProfileConfig presets
    ├── ranking.py           # Explainable candidate utility scoring and ranking
    ├── selection.py         # Constrained DP interval selection with structured exclusion audits
    ├── planning.py          # Boundary expansion, overlap resolution, and montage timeline mapping
    ├── rendering.py         # Subprocess FFmpeg clip extraction, profile normalization, and concat
    ├── validation.py        # Post-render stream probing and decode smoke test verification
    ├── pipeline.py          # Unified HighlightAssemblyPipeline orchestrator
    └── errors.py            # Domain exceptions (AssemblyRenderError, OutputValidationError, etc.)
```

## 2. Public API & Example Usage

The primary entry point is `HighlightAssemblyPipeline`:

```python
from pathlib import Path
from blazzid_assembly.config import AssemblyConfig
from blazzid_assembly.models import AssemblyProfile
from blazzid_assembly.pipeline import HighlightAssemblyPipeline
from blazzid_detection.detector import GameplayEventDetector

# 1. Detect gameplay candidates (Stage 3)
detector = GameplayEventDetector()
detect_result = detector.detect(Path("frames/"), source_duration_seconds=120.0)

# 2. Configure highlight assembly (Stage 4)
config = AssemblyConfig(
    profile=AssemblyProfile.PORTRAIT_9_16,  # 1080x1920 vertical montage
    target_duration_seconds=30.0,           # 30-second duration budget (e.g. YouTube Shorts)
    min_clip_duration_seconds=2.0,          # Do not select clips under 2 seconds
    max_clip_duration_seconds=10.0,         # Cap any individual clip at 10 seconds
    lead_in_padding_seconds=0.5,            # Add 0.5s context before action
    lead_out_padding_seconds=0.5,           # Add 0.5s resolution after action
)

# 3. Assemble and render highlight reel
pipeline = HighlightAssemblyPipeline(config=config)
result = pipeline.assemble(
    source_path=Path("raw_matches/brawl_stars.mp4"),
    candidates=detect_result.candidates,
    output_path=Path("renders/highlight_reel.mp4"),
)

if result.is_success:
    print(f"Rendered montage at {result.output_video_path}")
    print(f"Manifest written to {result.manifest_path}")
    print(f"Total duration: {result.edit_plan.total_duration_seconds:.2f}s "
          f"({result.edit_plan.selected_count} clips)")
else:
    print(f"Assembly failed: {result.error_message}")
```

## 3. Explainable Candidate Ranking & Scoring

Stage 3 event candidates are evaluated by `rank_gameplay_candidates` into normalized rank scores in $[0.0, 1.0]$. The score combines five explicit factors:

$$S = \left( w_{\text{conf}} \cdot C + w_{\text{cons}} \cdot S_{\text{cons}} + w_{\text{int}} \cdot S_{\text{int}} + w_{\text{dur}} \cdot S_{\text{dur}} \right) \cdot M_{\text{cat}} \cdot (1.0 - P_{\text{boundary}})$$

Where:
1. **Confidence ($C \in [0.0, 1.0]$, weight $w_{\text{conf}} = 0.40$)**: The calibrated heuristic confidence from Stage 3.
2. **Consensus ($S_{\text{cons}} = \min(1.0, 0.40 \cdot N_{\text{obs}})$, weight $w_{\text{cons}} = 0.25$)**: Bonus for corroborated observations from multiple independent detectors.
3. **Climax Intensity ($S_{\text{int}} \in [0.0, 1.0]$, weight $w_{\text{int}} = 0.20$)**: Normalized peak signal metric at event climax.
4. **Persistence ($S_{\text{dur}} = \min(1.0, \text{duration} / 8.0)$, weight $w_{\text{dur}} = 0.15$)**: Rewards sustained combat over fleeting single-frame spikes.
5. **Category Multiplier ($M_{\text{cat}}$)**:
   - `SUSTAINED_COMBAT`: $1.00$
   - `VISUAL_BURST`: $0.95$
   - `TEAM_WIPE`: $1.00$
   - `CLUTCH_KILL`: $1.00$
   - `GENERIC_HIGHLIGHT`: $0.70$
   - `SCENE_TRANSITION`: $0.30$ (transitions are structural markers, penalized in highlight ranking)
6. **Boundary Penalty ($P_{\text{boundary}} = 0.15$)**: Deducted if clip starts or ends within 2.0s of recording edges (where lead-in or resolution is truncated).

Candidates with $C < \text{min\_confidence}$ ($0.20$) are pruned. Results are sorted descending by rank score with deterministic tie-breaking.

## 4. Duration-Budgeted Selection & Exclusion Auditing

Selection wraps the 2D Dynamic Programming Weighted Interval Scheduling algorithm from `blazzid_algorithms.interval_selection`:
- **Discretization**: Durations are quantized into bins of size $\text{quantum\_bin\_seconds} = 0.5\text{s}$, with integer bin cost $c_i = \lceil \text{duration}_i / \text{quantum} \rceil$. Using ceiling ensures the continuous duration budget is never exceeded.
- **Zero-Overlap Guarantee**: Predecessor indices $p(i)$ are binary searched over interval end times, enforcing $end_j \le start_i$ for half-open intervals $[start, end)$.
- **Exclusion Audit**: Every unselected candidate is audited and assigned a structured `ExclusionReason`:
  - `DURATION_TOO_SHORT`: Duration $< \text{min\_clip\_duration\_seconds}$.
  - `DURATION_EXCEEDS_BUDGET`: Clip duration exceeds budget or $\text{max\_clip\_duration\_seconds}$.
  - `OVERLAPS_SUPERIOR_CANDIDATE`: Candidate temporally overlaps with a higher-ranked selected highlight.
  - `BUDGET_EXHAUSTED`: Duration budget was exhausted by higher-utility non-overlapping clips.
  - `MAX_CLIPS_REACHED`: Pruned when `max_clips_count` is reached.
  - `INSUFFICIENT_SEPARATION`: Pruned when separation from neighbor is under `min_separation_seconds`.

## 5. Clip Boundary Planning & Timeline Mapping

Selected candidates are converted to `PlannedClip` instances in `plan_edit_decision_list`:
1. **Context Expansion**:
   $$\text{start}_{\text{src}} = \max(0.0, \text{cand.start} - \text{lead\_in\_padding})$$
   $$\text{end}_{\text{src}} = \min(\text{source\_duration}, \text{cand.end} + \text{lead\_out\_padding})$$
2. **Overlap Resolution**: If context padding causes adjacent clips to overlap, a deterministic midpoint split is performed:
   $$\text{midpoint} = \frac{\text{clip}_i.\text{end} + \text{clip}_{i+1}.\text{start}}{2.0}$$
3. **Contiguous Montage Offsets**: Output montage intervals are assigned contiguously starting from 0.0s:
   - Clip 0: $[0.0, \text{dur}_0)$
   - Clip 1: $[\text{dur}_0, \text{dur}_0 + \text{dur}_1)$
   - Clip $k$: $[\sum_{j=0}^{k-1} \text{dur}_j, \sum_{j=0}^k \text{dur}_j)$

## 6. Rendering Architecture & Output Profiles

Rendering executes in three isolated subprocess stages via FFmpeg:

### Canvas Normalization Filter
To handle both landscape (16:9) and vertical short-form (9:16) targets without distortion or stretching:
```text
scale={w}:{h}:force_original_aspect_ratio=decrease,pad={w}:{h}:(ow-iw)/2:(oh-ih)/2:color=black,setsar=1,fps={fps}
```
- Landscape recordings fitted to 9:16 portrait are letterboxed with clean black padding bars.
- Landscape recordings fitted to 16:9 landscape scale directly to 1080p.

### Audio Policy
- **Source with Audio**: Original gameplay audio is extracted and normalized to stereo AAC 44.1kHz (`-c:a aac -ar 44100 -ac 2`). Audio/video synchronization is maintained via presentation timestamps.
- **Video-Only Source**: Omitted audio cleanly (`-an`). The pipeline handles audio-less media as a first-class citizen without failure.
- **No Injected Audio**: No synthetic music or external sound effects are introduced.

### Fast Concat Demuxer
Because all extracted clip segments are normalized to identical codec (`libx264`), pixel format (`yuv420p`), resolution, and audio parameters, concatenation executes using the FFmpeg concat demuxer with stream copy (`-c copy -movflags +faststart`). This achieves near-instantaneous concatenation with zero generation loss.

### Predefined Profiles

| Profile Name | Resolution | Aspect Ratio | Codec | Audio |
| :--- | :--- | :--- | :--- | :--- |
| `PORTRAIT_9_16` | $1080 \times 1920$ | 9:16 (Shorts/Reels) | H.264 CRF 22 | AAC 44.1kHz Stereo |
| `LANDSCAPE_16_9` | $1920 \times 1080$ | 16:9 (Standard) | H.264 CRF 22 | AAC 44.1kHz Stereo |
| `DEV_PORTRAIT` | $360 \times 640$ | 9:16 (Test/Dev) | H.264 CRF 24 | AAC 44.1kHz Stereo |
| `DEV_LANDSCAPE` | $640 \times 360$ | 16:9 (Test/Dev) | H.264 CRF 24 | AAC 44.1kHz Stereo |

## 8. Post-Render Validation & Quality Assurance

Rendered videos undergo an independent 6-point verification battery in `validate_rendered_montage`:
1. **File Check**: Non-empty regular file on disk.
2. **Container Inspection**: Probed via `ffprobe` to verify container headers.
3. **Video Dimensions**: Actual frame width and height strictly match the target profile.
4. **Audio Stream Policy**: Probed audio presence matches the source media contract.
5. **Duration Tolerance**: $| \text{actual\_duration} - \text{planned\_duration} | \le 0.75\text{s}$.
6. **Decode Smoke Test**: Executes `ffmpeg -v error -i output.mp4 -f null -` to verify that all frames and audio packets decode cleanly without container errors.

## 10. Limitations & Known Failure Modes

1. **Aspect Ratio Padding**: The initial baseline uses black pillarbox/letterbox padding for incompatible aspect ratios (e.g. 16:9 gameplay rendered to 9:16 portrait). It does not include subject-aware cropping or brawler tracking.
2. **Audio Ducking & Music**: The pipeline preserves original gameplay audio in sync, but does not mix background music or perform audio ducking.
3. **Keyframe Snapping**: While seek commands use `-ss` with re-encoding, minor fractional-frame deviations ($\le 0.1\text{s}$) may occur due to container presentation time base quantization.
